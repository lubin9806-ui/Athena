## 一、已验证主 Demo

### 任务名称

修复一个存在多处缺陷的 Node.js 统计模块，并运行测试直到全部通过。

### 为什么选择这个任务

这不是一段宣传片，也不是单次文本生成。它要求 Athena 在真实 Windows 环境中完成一条可检查的任务链：

1. 接收自然语言目标和约束；
2. 查看项目目录并读取 `stats.js`、`test.js`；
3. 运行 `node test.js`，取得真实失败结果；
4. 根据结果定位两个独立缺陷；
5. 在修改前展示目标路径、原文和替换内容并等待授权；
6. 保持 `test.js` 不变，修改 `stats.js`；
7. 再次运行测试；
8. 汇总修改内容并交付结果；
9. 由 E2E 脚本独立检查测试退出码和 `test.js` 哈希。

该任务同时覆盖任务理解、动态规划、多个工具调用、Windows 命令执行、文件读取与修改、逐项权限审批、错误反馈、再次验证和最终交付，能够集中体现“超级智能体”而非普通 Chatbot。

## 二、模型与执行边界

- 规划模型：用户已配置的 DeepSeek `deepseek-v4-pro`。
- 执行环境：Athena 当前源码构建的真实 Electron Renderer。
- 本地工具：目录读取、文件读取、命令执行、文件修改均由 Athena 在本机完成。
- 网络边界：只将脚本生成的虚构示例代码发送给模型；工具联网、Web Search、云同步、语音和自动记忆均关闭。
- 权限：Execute 为 `full`，但保持“逐项审批”；每个命令或写入动作都在真实界面展示参数。
- 数据：不包含仓库业务源码、私人文件、学校联系人信息或 API Key；凭据由 Electron `safeStorage` 读取，不复制到参赛材料。

## 四、拍摄与剪辑原则

- 真实运行片段保持原始时间顺序，不重排工具步骤。
- 不覆盖 Athena 自身状态，不用后期字幕把“未验证”改成“已验证”。
- 明确区分“产品内未配置验收项”和“外部测试脚本独立通过”。
- 模型名称、任务路径、审批参数和执行结果均来自真实运行。
- 允许在真实片段前后加入封面、说明、冻结画面和文字旁注，但不能伪造鼠标操作、审批卡或测试结果。
- 不宣称 Athena 具备通用鼠标、键盘或任意 GUI 自动化；本 Demo 使用文件和命令工具。

## 五、不要剪掉的证据

1. 首次 `node test.js` 的审批卡与失败结果。
2. Athena 读取 `stats.js` 和 `test.js` 的过程。
3. 两项文件修改审批，至少完整保留一项原文与替换内容。
4. 第二次 `node test.js` 审批与退出码为 0 的结果。
5. Athena 最终说明中“test.js 没动”的约束遵守情况。
6. UI 的“未验证”状态，以及字幕对该边界的如实解释。
