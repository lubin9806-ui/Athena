# Athena 需要补拍的截图清单

目标：补齐当前仓库现有空状态 UI 截图无法证明的真实 Agent 执行链。所有截图应来自 `0.9.7-beta.1` 当前构建或最终比赛候选构建，保留系统时间、真实窗口边界和必要路径；使用专用演示账户与虚构数据，禁止出现密钥、私人聊天或真实联系方式。

## 一、必须补拍：完整任务闭环

### 1. 演示输入与 Project 边界

- [ ] Windows 资源管理器中的演示输入目录，能看到 `活动说明.md`、`人员分工.csv`、`时间安排.png` 的名称、大小和修改时间。
- [ ] Athena 持久化 Project 首页，清楚显示 Project 名称、目标和工作目录；不能是 Temporary Chat。
- [ ] 三个附件已加入聊天、完整用户目标尚未发送的画面。

### 2. 任务创建与动态执行

- [ ] 发送后生成的 task/run 状态，包含任务 ID 或可识别标题、开始时间和运行状态。
- [ ] `extract_text_from_images` 正在运行的画面。
- [ ] OCR 完成后的工具结果，能看到引擎、本地图像数量与提取摘要，但不必展示大段原始文本。
- [ ] 至少两个连续工具事件及其顺序，证明模型在收到结果后继续执行。
- [ ] 模型或执行状态对“不访问网络、不修改输入文件”约束的体现。

### 3. 权限与审批

- [ ] 当前逐项审批实现中的 `create_document_artifact` 审批卡，必须显示工具名、PDF 文件名、目标 Project artifact 目录、写入原因和风险等级。
- [ ] 用户点击批准前的 awaiting approval 状态。
- [ ] 批准后同一 run 恢复执行的状态。
- [ ] 可选：执行预算用尽后的“继续执行 / 停止并总结”卡片，展示已用轮次、工具次数和拟追加预算。
- [ ] 可选：用户拒绝一次无关高风险调用后的安全收敛，用于答辩备用，不放主视频。

### 4. 成果与验证

- [ ] 文档工具完成后的结果，能看到 artifact ID、绝对路径、字节数、SHA-256 和 validation status。
- [ ] Athena Project 成果区中的 `AI杭州演示执行简报.pdf`。
- [ ] Windows 默认 PDF 阅读器打开成果后的全页画面，正文应包含目标、日程、分工、风险和检查清单。
- [ ] 输出目录录制前后对比，能看到新文件的修改时间和大小。
- [ ] task/run 最终状态、总时长、工具调用次数和交付物数量。
- [ ] 若总体显示 `unverified`，补拍完整提示；不要裁掉，应在说明中区分“文件完整性通过”和“总体内容验收未配置”。

## 二、建议补拍：支撑评审维度

### 5. 本地记忆

- [ ] 使用纯虚构项目数据的记忆抽屉，展示事件、摘要、事实来源与 Project 隔离。
- [ ] 在第二个会话中用明确项目关键词召回上一会话事实，并同时拍到来源证据。
- [ ] 可选：展示同义改写失败样本，作为当前语义检索缺口的诚实证据，不用于主宣传页。

### 6. 多模型与本地优先

- [ ] 模型设置页，显示 Ollama 与 OpenAI-compatible 供应商选项；所有 API key 字段必须遮蔽且不可通过开发者工具泄露。
- [ ] 现场实际使用模型的 ready 状态与模型名。
- [ ] 外部网络关闭、本地 OCR 与本地模型仍可完成 Demo 的状态。

### 7. 语音与多模态

- [ ] 在比赛设备上真实按下录音、出现音量/录音状态、完成中文转写的连续三张截图。
- [ ] 本地语音模型/运行时 ready 状态。
- [ ] TTS 播放与打断状态；只有真实扬声器验证成功后再使用。
- [ ] 图像附件缩略图、OCR 工具和最终日程三者对应的证据链。

### 8. 权限与安全

- [ ] `off/read/files/full` 四级权限设置，并明确 Execute 以外模式保持 off。
- [ ] 模型请求同意与外部网络同意开关。
- [ ] 运行中把权限从 full 收紧后，当前 run 无法继续调用高等级工具的测试画面。
- [ ] 当前逐项审批参数与实际执行事件的并排截图，证明显示内容和执行内容一致。

## 三、不应补拍或不应使用

- [ ] 不拍“鼠标自动点击任意应用”的画面；当前仓库没有通用 GUI 自动化。
- [ ] 不把 Live2D、Athena Cloud、商店上架、签名安装包做成已完成能力画面。
- [ ] 不把 PDF 输入解析用于主 Demo；当前链路有缺陷。
- [ ] 不把 `docs/brand/` 中的概念板、角色原型或静态空状态当作任务执行证据。
- [ ] 不用后期制作的工具名称、进度条或“验证通过”字幕覆盖真实 UI。
- [ ] 不展示真实用户目录、个人邮箱、手机号、云密钥、浏览器 cookie 或私有项目内容。

## 四、拍摄规格

- 分辨率：优先 1920×1080；截图保存 PNG。
- 命名：`01-project-input.png`、`02-goal-before-send.png`、`03-task-running.png`……按执行顺序编号。
- 同一轮素材使用相同主题、窗口大小、Project 和模型。
- 每张截图附一行记录：构建版本、拍摄日期、设备、模型、是否联网、对应 task/run ID。
- 主说明书只选 6—8 张；其余作为答辩证据附件保留。

## 五、仍需人工提供的非截图材料

- [ ] 参赛团队名称、学校、学院、指导教师、成员姓名与分工。
- [ ] 赛事报名编号、联系人、版权声明和需要盖章的主体信息。
- [ ] Athena 品牌标记的最终公开使用确认或替代 Logo 主文件。
- [ ] 真实用户试用数据：样本量、任务成功率、平均耗时、人工接管次数与典型反馈。
- [ ] 最终比赛候选构建的签名/安装方式说明；若仍未签名，应继续标注为私测候选版。
- [ ] 一条当前版本的无剪辑端到端 Demo 原始录像。
