Athena 参赛摘要
材料基线：Athena 0.9.7-beta.1，2026-09-15 当前仓库

【A. 100字项目简介】

Athena 是面向个人用户的本地优先 Windows 自主桌面 AI Agent。它理解自然语言目标，在持久化项目中连续调用文件、终端和程序工具，高风险操作请求授权，并记录任务状态与交付物，让 AI 从回答问题走向受控完成真实任务。

【B. 300字项目介绍】

Athena 是面向个人用户的本地优先 Windows 自主桌面 AI Agent。与只提供建议的 Chatbot 不同，它将自然语言目标转为持久化任务，由支持原生工具调用的模型根据真实工具结果持续决定下一步，调用文件读写、目录检索、命令、终端、程序、HTTP、OCR 和文档生成等能力。系统以 off、read、files、full 四级权限、网络同意和高风险审批控制边界，并把任务、步骤、事件、证据和交付物保存在本地 SQLite。Athena 支持 Ollama 与 OpenAI-compatible 模型、本地多层记忆、项目隔离、语音和多模态附件。当前 0.9.7-beta.1 为私测候选版；Agent 主链已实现，但通用 GUI 控制、细粒度可视计划和普通任务自动验收仍不完整。

【C. 800—1200字作品详细描述】

Athena 的核心定位是“本地优先的自主桌面 AI Agent”。它面向需要处理个人资料、项目文件和 Windows 工作流的用户，解决传统 AI Chatbot 与真实操作之间的断层：AI 能够解释应该如何做，但创建目录、整理文件、运行命令、检查服务、保存成果和处理失败，仍要由用户逐步完成。

用户在持久化 Project 中提出目标后，系统完成路由、用户同意和项目边界检查，创建任务、运行和起始步骤，检索项目上下文与本地记忆。支持原生工具调用的模型随后进入受限循环：理解状态、选择工具、接收真实返回并决定下一步，直至完成、取消、失败或达到预算。当前默认预算为 16 轮模型调用和 48 次工具调用，耗尽后由用户决定是否追加。

Athena 提供 22 个 Windows 工具，覆盖文件与目录读写检索、复制移动删除、命令、持久终端、程序启动、路径打开、HTTP 和端口检查；同时接入本地 OCR、Markdown/HTML/DOCX/PDF 成果生成、Skills 文本资源、MCP 及实验性研究工具。任务、步骤、事件、审批、证据和交付物写入本地 SQLite，可暂停等待授权、取消、记录失败，并仅对安全或幂等调用自动重试。

安全边界是产品主链的一部分。计算机权限分为 off、read、files、full 四级并默认关闭，只有 Execute 可获得权限；模型请求、外部网络和高风险动作分别受同意或审批控制，运行中撤权会降低任务权限上限。待审批调用会逐项展示关键参数并支持逐项决定；自动执行位置和追加写入会触发提示。Renderer 启用 sandbox 和 context isolation，密钥由 safeStorage 加密且不下发 Renderer。

Athena 支持 Ollama 与 OpenAI-compatible 模型，具备会话上下文、用户事实、情景事件、每日摘要、项目笔记和带来源事实等本地记忆；支持图像、文本、DOCX、XLSX 等附件，以及 faster-whisper 本地语音识别和 Piper/Windows SAPI 语音输出。用户可优先使用本地模型、OCR 和语音，授权后再连接外部服务。

当前 0.9.7-beta.1 为私测候选版。仓库验证表明 Agent 循环、任务持久化、权限撤销、桌面 smoke、语音依赖、附件、OCR 与成果生成均有证据；但尚无通用鼠标、键盘和屏幕控制；细粒度计划主要在循环中动态形成，缺少执行前可视化；普通任务未自动配置验收条件，部分结果会标记未验证；PDF 项目文档导入存在缺陷；真实云模型、真实麦克风、签名安装包和干净设备不在本次验证范围。

Athena 的创新不在于给 Chatbot 增加更多按钮，而在于把“目标—工具—权限—状态—证据—交付”组织成个人任务系统，让 AI 从“回答问题”走向“在用户授权下完成任务”，同时让用户知道它做了什么、何时需要确认、结果是否经过验证。
