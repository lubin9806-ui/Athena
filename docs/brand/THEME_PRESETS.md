# Athena · 三套主题方案

用户最新决定优先于之前“替换旧逻辑”或“只保留一个工作台”的方向。

| 方案 ID | 名称 | 角色 | 当前依据 |
| --- | --- | --- | --- |
| `daylight` | 日光 | **默认主题** | 已完成的 companion-prototype，包含局部玻璃、消息动效和稳定布局 |
| `classic` | 经典 | 可选，保留现软件界面 | 当前真实 renderer；不是 companion-prototype 的另一种配色 |
| `atelier` | 随心桌面 | 已登记的开发中选项 | atelier-prototype，以想法对象、关联和聚焦展开为中心；尚未接入正式运行时 |

日光 / 夜色是每套主题内部的色调，不另算三套主题之一。随心桌面属于布局与交互方案，不只是更换 CSS 颜色。

## 不可变品牌资产

- 已确认的 Athena Logo、字标与功能图标不随主题更换，不重新生成，不制作主题专属变形版本。
- 原型共用 `companion-prototype/assets/athena-mark.svg` 和 `icons.svg`；其现有来源、精度说明保持有效。正式接入应复用同一资产入口，而非在三个目录复制三套可漂移资源。
- 新生成的参考图仅用于构图与材质；图内自动生成的标志不能替换已确认的标志。

## 正式软件接入设计

1. 提供“主题与布局”选择器：日光为默认，经典可立即切换；随心桌面在完成真实数据接入前显示为不可应用的开发中选项。
2. 将共同业务状态放在界面方案之外：聊天、记忆、人格、模型配置、权限、草稿和项目只保留一份。
3. 各主题以同一业务命令驱动同一数据源，不复制控制器或为不同主题创建独立数据库。
4. 主题切换不得取消正在执行的任务或遗失草稿；无法安全切换的瞬间显示明确等待状态。
5. 初次进入随心桌面时，应从共享内容投影出想法对象，不能悄悄把现有聊天改造成任务。对象与聊天的对应关系仍需要在后续迁移阶段定义并验证。
6. 当前用户继续使用经典方案的显式选择应被保留；新安装使用日光。迁移不覆盖用户已有外观偏好。
7. 权限边界与功能能力不随主题改变；新颖交互不扩大模型、文件或电脑工具权限。

## 当前正式接入状态

- `daylight` 已作为空配置与新安装的正式默认主题接入 renderer。
- `classic` 已作为可用选项接入；点击后仅通过外观专用 IPC 保存，不重载模型、不新建对话，也不复制数据库。
- `atelier` 已进入同一方案注册表，但界面明确标为“开发中 · 尚不可应用”。若历史配置包含该值，会保留用户偏好并安全显示日光主题。
- 日光与经典共用一套业务状态、权限边界、品牌标志和功能图标；主题只改变布局与视觉呈现。
- 已确认的标志已接入标题栏和 favicon，并由同一源文件生成 Windows 应用、安装包与托盘所需格式。
- 本轮没有修改用户配置、数据库、聊天、人格或模型内容；验证使用隔离的临时配置目录。

独立原型仍用于后续设计验证。**随心桌面尚未共享正式业务数据，不能据此声称跨主题数据投影已经完成。**
