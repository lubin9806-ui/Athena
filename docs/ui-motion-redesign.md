# Athena UI 与动效方案：Lumen Workspace

## 1. 设计结论

Athena 的新界面不是手机系统皮肤的复刻，而是提取 Apple 与 OPPO 动效中真正适合桌面助手的部分：清晰层级、克制材质、空间连续性，以及简短而有物理感的反馈。

整套方案只有一句设计原则：

> 内容层静，控制层浮，状态变化连续。

- **内容层静**：聊天内容与背景保持稳定，不使用粒子、网格、轨道或持续流动的彩色光影。
- **控制层浮**：标题栏、模式切换、输入框和抽屉使用轻量玻璃材质建立层级。
- **状态连续**：模式、面板、菜单和消息从其触发位置自然展开，并能随时被下一次操作打断。

## 2. 参考原则

本方案参考以下官方设计资料，但不复制其品牌视觉：

- [Apple Human Interface Guidelines — Motion](https://developer.apple.com/design/human-interface-guidelines/motion)：动效应简短、准确、有目的，并尊重“减少动态效果”。
- [Apple Human Interface Guidelines — Materials](https://developer.apple.com/design/human-interface-guidelines/materials)：材质用于表达结构和前后层级，不能牺牲文字对比度。
- [Apple Human Interface Guidelines — Layout](https://developer.apple.com/design/human-interface-guidelines/layout)：相关控制应成组，主要内容优先，导航与控制可浮于内容之上。
- [OPPO ColorOS 16 — Seamless Animation](https://www.oppo.com/en/newsroom/stories/oppo-find-x9-series-coloros-16-smooth/)：变化从触点发生，并在关闭时回到来源，保持空间关系。
- [OPPO ColorOS 15 — Smooth Interaction](https://www.oppo.com/en/newsroom/stories/oppo-coloros-15-launch-smooth/)：使用克制、灵活的回弹模拟自然物理反馈，并允许多个过渡并行发生。

## 3. 信息架构

### 3.1 第一层：高频对话

默认窗口只保留完成一次对话所需的内容：

1. 标题栏：身份、连接状态、记忆、设置、窗口控制。
2. 模式轨道：创作、陪伴、推理。
3. 消息流：助手内容使用开放式排版，用户内容使用轻量气泡。
4. 输入岛：更多、文本输入、麦克风、发送。

### 3.2 第二层：低频工具

- “更多”使用输入框原位弹出菜单，承载文件、音频转写与朗读。
- “记忆”和“设置”使用右侧浮动抽屉，不跳转页面，不丢失对话上下文。
- 同一时刻只允许一个抽屉；`Esc`、遮罩与再次点击入口均可关闭。

## 4. 视觉系统

### 4.1 色彩与材质

| Token | 建议值 | 用途 |
| --- | --- | --- |
| `--bg` | `#090a0d` | 稳定的应用背景 |
| `--surface` | `#14161b` | 普通卡片与输入区域 |
| `--surface-raised` | `#1b1d24` | 抽屉、弹层和浮动控件 |
| `--glass-control` | `rgba(29, 31, 38, .70)` | 标题栏、模式轨道、输入岛 |
| `--text-primary` | `#f6f4f2` | 主要信息 |
| `--text-secondary` | `#b7b3b0` | 辅助信息 |
| `--text-muted` | `#77777f` | 低优先级说明 |
| 创作强调色 | 冷蓝 | 聚焦、发送、选中态 |
| 陪伴强调色 | 柔粉 | 陪伴模式语义 |
| 推理强调色 | 暖金 | 推理模式语义 |

材质规则：

- 玻璃只用于控制层，不铺满整页。
- 模糊必须配合半透明实色和清晰描边，保证弱显卡或关闭透明效果时仍可读。
- 强调色只服务当前模式、主要动作和短时状态，不作为大面积背景。
- 环境光是静态、低对比的色温，不允许持续漂移。

### 4.2 圆角与间距

- 小控件：`13px`。
- 输入岛与大型卡片：`20px`。
- 浮动抽屉：`24px`。
- 以 `4px` 为基础单位，主要使用 `8 / 12 / 16 / 20 / 24px`。
- 正文字号以 `14px` 为基准；辅助说明使用 `11–12px`，不再堆叠装饰性超小文字。

### 4.3 层级

| 层级 | 内容 | 视觉处理 |
| --- | --- | --- |
| L0 | 背景 | 静态深色与极弱环境光 |
| L1 | 对话内容 | 无玻璃、少边框、强调可读性 |
| L2 | 标题栏、模式轨道、输入岛 | 半透明控制材质与短阴影 |
| L3 | 菜单、抽屉 | 更高不透明度、描边、明显但柔和的景深 |
| L4 | 状态反馈 | 局部颜色和微动，不改变页面布局 |

## 5. 动效系统

### 5.1 时间与曲线

| Token | 时长 | 用途 |
| --- | ---: | --- |
| `--motion-fast` | `120ms` | hover、按压、图标反馈 |
| `--motion-standard` | `220ms` | 菜单、消息、颜色与透明度 |
| `--motion-emphasis` | `360ms` | 抽屉、模式滑块、较大空间变化 |
| `--ease-standard` | `cubic-bezier(.2, .8, .2, 1)` | 普通过渡 |
| `--ease-spring` | `cubic-bezier(.16, 1, .3, 1)` | 轻量物理回弹 |

### 5.2 组件动效映射

| 场景 | 时长 | 空间来源 | 行为 |
| --- | ---: | --- | --- |
| 窗口首次出现 | 180ms | 窗口中心 | 透明度淡入并上移不超过 4px |
| 模式切换 | 340ms | 当前选项 | 单个选中滑块平移，文字颜色并行过渡 |
| 助手消息 | 260ms | 内容左侧 | 淡入并向右移动 4px |
| 用户消息 | 280ms | 输入岛方向 | 淡入并向上移动 5px |
| “更多”菜单 | 220ms | “更多”按钮 | 从左下方缩放至 100%，图标同步旋转 |
| 右侧抽屉 | 360ms | 右侧入口 | 浮动面板从右侧进入，遮罩在 280ms 内并行淡入 |
| 抽屉标签 | 320ms | 当前标签 | 单个选中底板横向滑动 |
| 思考反馈 | 1250ms 循环 | 状态点 | 只在模型实际工作时轻微呼吸 |
| 录音反馈 | 1150ms 循环 | 麦克风 | 只在实际录音时显示计时和局部呼吸 |

### 5.3 动效纪律

- 所有过渡都必须可打断；用户连续切换时直接从当前视觉状态前往新状态。
- 同一次操作涉及的透明度、位移、遮罩和选中态应并行执行，避免排队播放。
- 常规位移不超过 `6px`；抽屉除外，但只沿进入方向运动。
- 按压反馈使用 `scale(.97–.98)`，不使用夸张弹跳。
- 不为背景、头像、装饰线或空闲按钮增加无限循环。
- 动效只解释“发生了什么”和“从哪里发生”，不承担装饰任务。
- `prefers-reduced-motion: reduce` 下取消位移、缩放和循环，只保留近乎即时的状态切换。

## 6. 关键交互状态

### 6.1 模型状态

- **就绪**：绿色状态点，界面完全静止。
- **工作中**：当前模式强调色轻微呼吸，发送按钮进入不可重复提交状态。
- **离线**：标题栏内直接显示“Ollama 离线”，不使用阻断式弹窗。
- **错误**：状态点与简短错误文本变红，详细信息放入可展开区域。

### 6.2 面板状态

- 打开抽屉后入口按钮保持选中，`aria-expanded` 与 `aria-hidden` 同步更新。
- 打开另一个抽屉时直接完成空间交接，不先退回主界面再重新进入。
- 遮罩只降低背景注意力，不模糊对话正文到不可识别。

### 6.3 输入状态

- 空输入时发送按钮保持低权重；有内容后才提升为当前强调色。
- 录音、发送、等待与错误状态均在输入岛原位反馈，不让布局跳动。
- “更多”菜单点击外部区域或按 `Esc` 立即关闭。

## 7. 性能与实现边界

- 不加载 Three.js，不创建 WebGL 画布。
- 不保留粒子、网格、轨道和持续变化的彩色灯效。
- 优先使用 `transform` 与 `opacity`，减少布局重算。
- 模糊材质提供不透明后备样式，低性能环境仍保持完整层级。
- Renderer 主脚本构建后保持在 `40KB` 以内（未压缩目标）。
- 所有动画 token 统一定义于 CSS，不在组件中散落任意时长。

## 8. 验收标准

- `480 × 700` 默认窗口内完整显示标题栏、模式、消息流与输入岛。
- 高频对话入口不超过 7 个；低频操作进入菜单或抽屉。
- 记忆与设置不发生页面跳转，并支持入口、遮罩和 `Esc` 三种关闭方式。
- 模式滑块、菜单、抽屉和标签切换的视觉来源清晰，连续快速操作无排队感。
- 就绪状态没有任何持续动画；仅工作中和录音中允许局部循环。
- 键盘焦点、ARIA 展开状态和减少动态效果模式均可用。
- TypeScript 类型检查、Vite 构建和 Electron smoke 测试全部通过。
- Smoke 输出包含 `ATHENA_SMOKE_READY_TO_SHOW` 与 `ATHENA_SMOKE_DOM_OK`。

## 9. 本轮落地范围

本轮已将上述视觉层级、模式滑块、来源感消息动效、输入菜单、浮动抽屉、标签滑块、状态动效与减少动态效果支持直接落入 Athena Renderer。它是一套可以继续扩展的生产基线，而不是独立概念稿。
