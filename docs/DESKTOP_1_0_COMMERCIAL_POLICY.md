# Athena Desktop 1.0 商业政策冻结稿

> 窗口 07 / ATH-DESKTOP-002。基线日期：2026-07-16。本文冻结产品和流程边界，但不是已生效销售条款。公司主体、域名、支付与许可证平台、价格、税务和公开联系地址均未确定；对应字段在 `config/commercial.json` 中必须保持 `null`，不得用虚构信息代替。

## 1. SKU 与收费边界

Desktop 1.0 只设一个直售 SKU：`athena-desktop-personal-v1`，展示名为 **Athena Desktop 1.x Personal**。

- 授权方式：个人用户一次性购买，不要求 Athena 账号。
- 版本权益：覆盖 Desktop 1.x 的维护和功能更新；未来 2.0 是否收费另行公布。
- 设备权益：同一购买者最多同时激活 2 台本人使用的 Windows 设备。
- 1.0 不设 Free/Pro 分层、不设订阅、不包含云额度，也不承诺跨设备同步。
- 价格、币种、税费、销售区域和优惠未冻结；在这些字段确定前不得展示购买按钮或接受付款。
- Private Beta 不是付费 SKU，不得向测试者收费或暗示已经预售。

## 2. 1.0 权益范围

正式 SKU 只能承诺通过发布门的 Windows 功能。当前候选边界为：

- Windows 10/11 x64 桌面应用；
- 用户自备 Ollama 与兼容本地模型的本地优先对话；
- Create、Companion、Reason 三种普通模式；
- 本机聊天记录和可管理长期记忆，以及 JSON/Markdown 导出与本机清除；
- 主题、托盘和设置中心；
- Execute 电脑操作作为单独标注的 Beta 能力，默认 Off，需显式授权与高风险逐次确认。

语音、实验性网页搜索、进程内提醒和工作流骨架只有在各自 GA 门通过后才能加入正式卖点。Live2D、音乐、日历、云同步、账号、Steam、Mobile、macOS 和 Linux 均为 Planned 或 Excluded，不属于 Desktop 1.0 购买权益。

## 3. 激活与离线行为

生产设计采用可替换 `LicenseAdapter`：支付平台只负责交易，许可证平台把购买凭证换成针对设备的签名 entitlement；客户端只保存 entitlement，不保存原始许可证密钥或支付信息。

1. 用户输入许可证密钥并同意向未来许可证平台发送密钥、SKU、应用版本和设备标识。
2. 平台验证最多 2 台活动设备，返回签名 entitlement。
3. 客户端用内置公钥离线验证。1.0 不要求周期性联网续租。
4. 激活服务暂时不可用时，已激活设备继续离线使用；新激活和停用可能需要等待服务恢复。
5. entitlement、公钥、设备标识算法和安全存储尚未生产实现；当前只有显式 opt-in 的本地测试适配器，不构成真实激活。

## 4. 换机与恢复

- 正常换机：旧设备联网停用，再在新设备激活；停用立即释放一个设备名额。
- 无法访问旧设备：通过支持入口提交购买证明并申请人工重置；目标为每份许可证每滚动 12 个月最多 2 次人工设备重置。
- 不转售许可证，不支持多人共享、组织席位或批量部署；这些需要未来独立 SKU。
- 停用、重置或退款只改变软件权益，不删除用户本机数据。用户仍可导出或清除数据。

## 5. 退款规则

- 自购买完成起 14 个自然日内可申请自愿退款；适用法律提供更长或更强权利时，以法定权利为准。
- 退款通过未来支付平台原路处理；具体到账时间、税费和地区例外必须在接入平台后公布。
- 退款完成后撤销对应许可证及设备 entitlement；客户端不得远程删除用户文件、聊天或记忆。
- 重复退款、拒付和欺诈处理需由真实支付条款和法律复核决定，本稿不预设虚构规则。

## 6. 支持、隐私与安全入口

入口信息由 `config/commercial.json` 统一注入官网、应用和发行材料。当前均未确定，因此生产门保持关闭。

| 渠道 | 目标用途 | 首次响应目标 | 当前状态 |
|---|---|---:|---|
| 支持 URL / 邮箱 | 安装、激活、换机、退款、可复现故障 | 2 个工作日 | 未配置 |
| 隐私邮箱 | 数据权利、隐私疑问、第三方联网说明 | 5 个工作日 | 未配置 |
| 安全邮箱 | 漏洞报告、泄露或高风险执行问题 | 1 个工作日确认收到 | 未配置 |

不得把 GitHub issue、个人邮箱或不存在的状态页临时写成正式支持渠道。公开入口确定后，应在应用内“隐私与数据中心”、安装器、官网、隐私政策和 EULA 中保持一致。

## 7. 可替换接口与生产接入门

代码边界位于：

- `src/core/commercial/CommercialPolicy.ts`：加载并验证商业配置，列出生产阻断项；
- `src/core/commercial/LicenseService.ts`：激活、离线校验和停用状态机；
- `src/shared/types/commercial.ts`：支付无关的 `LicenseAdapter`、`LicenseStore` 和 entitlement 契约；
- `scripts/verify-commercial-readiness.js`：设备上限、换机、篡改、版本边界、测试适配器门和营销禁词回归。

接入真实平台前必须完成：主体/销售区域/税务复核、价格币种、支付条款、许可证供应商与 SLA、公开密钥轮换、设备标识隐私评审、安全存储、断网/撤销/恢复测试、应用内激活 UI、公开 URL 和人工签字。完成前 `releaseStage=prelaunch`、`provider.mode=unconfigured`，并保持 **No-Go**。
